# File-export document isolation

The UI runs `file.bounce_mix`, `file.bounce_stems` and `session.save_copy` against a detached Engine. Existing live opaque plugin-state bytes are applied only to that copy, including instrument state. The modal Bounce Mix path uses the same detached construction. Export success, refusal and cancellation leave the active document, revision, dirty state, history, path, command journal and recovery bookkeeping unchanged. Save Copy does not close the original document's recovery session.

Ordinary Save, Save As and Save As Template retain their existing capture behavior. Track Commit, Track Bounce and Freeze remain document-edit operations. Other exports keep their existing behavior. Detached exports retain the original Session folder and engine path and execute under the current file-access gateway scope; this does not grant additional filesystem authority.

This change isolates document writes. It does not establish that the existing `Player::capture_states` bytes belong to the exact exported document generation. That API can omit unavailable states and does not provide a fallible document-bound capture receipt. Pending editor gestures, same-ID instance generations, capture synchronization, and browser live-state capture remain separate work. Capture may still call existing plugin serialization even when later export validation refuses the request. No stronger freshness, realtime or processor-consumption claim is made.

A private test-only capture provider feeds the same capture function used by both ordinary saves and detached exports. Deterministic tests exercise actual direct Save Copy with captured bytes, stale capture refusal through direct and modal Bounce, clean-document recovery retention, detached insert/instrument byte overlays and reopen a saved copy to verify the serialized bytes, partial overlay failure, all three direct command routes, modal start/drop cancellation/refusal, scoped destination refusal, existing undo/redo stacks and ordinary save behavior. They do not require an installed third-party plugin and do not prove native editor behavior. Rendered UI smoke and standard repository checks are separate validation gates.
